**Goal:** Make SpecX spec `${PROJECT_NAME} - Milestones` accurately reflect implementation and verification state.

**Scope:** Update only the selected milestone's status and implementation/verification notes in that SpecX spec, plus directly required project documentation. Do not mark incomplete work done. Never write a local milestones markdown file.

**Definition of Done:** Status is `done`, `blocked`, or accurately remains `in_progress`; notes contain sufficient evidence for another agent to understand the result and next action.

Actions:

- Set status to `done` only when every acceptance criterion passes.
- Set status to `blocked` with evidence and next action when progress cannot continue.
- Leave `in_progress` only when the session ends before completion, with remaining work recorded.
- Add an implementation and verification note to the milestone in SpecX.
